# 抖音评论调研工作台

本项目使用 Python 3.12、Playwright 和系统 Google Chrome，采集抖音一级评论文字及评论图片，并通过本地网页完成全部日常操作。

## 功能

- “并发采集”开关默认关闭；开启后最多同时采集两个视频，共用登录会话但独立监听评论、保存数据和日志。日志标记对应视频；队列每行的停止图标仅停止该视频，页面“停止整批”停止全部任务。遇到登录或验证会暂停派发新任务，手动处理后点击继续；并发会增加请求量和触发验证的可能性；

- 输入抖音视频链接后启动或停止采集；
- 视频链接默认显示一个输入框，点击每行右侧的“+”新增一行（最多 100 个）；忽略空行，自动去重后逐个采集，每个视频独立保存结果和日志，单个失败继续下一个，停止整批后不再启动剩余视频；
- 遇到登录、滑块或安全验证时，由用户在 Chrome 中手动完成，再在网页点击继续；
- 评论层级可选择“仅一级评论”（默认）或“所有层级评论”；
- 一级评论默认复用浏览器捕获的真实 `comment/list` 请求按游标分页；若接口签名失效、游标不前进或请求异常，会保留已有数据并自动切回页面滚动；
- “所有层级评论”采用两阶段采集：先快速加载完全部一级评论，再回到顶部逐段展开全部回复；该模式不会因评论数或运行分钟上限自动截断；
- 保存评论文字、作者、时间、IP 属地、点赞数、回复数及评论图片；
- 可开启“获取抖音号”（默认关闭）：评论采集后，优先使用评论接口的 `unique_id`；缺失时按 `sec_uid` 去重访问用户主页，读取 `user/profile/other` 响应的 `user.short_id`，回填 `author.unique_id`。同一任务内每位用户只补充一次；额外访问主页会影响性能、增加耗时；
- `author.unique_id_source` 标记抖音号来源：`comment_api`（评论接口）、`profile_api`（主页接口）。运行日志也逐用户说明来源；未获取到时保留空值，不使用内部用户 ID 替代；
- WebP 图片自动转换为 JPEG；
- 浏览历史结果、搜索评论、仅看带图评论、按点赞数或时间排序；
- 在网页中生成并下载 Excel；
- 每次采集建立新的 `output/<时间>-<视频ID>/` 目录。

## Windows 首次安装

安装 Python 3.12 和 Google Chrome，然后在项目根目录执行一次：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
```

项目直接使用系统 Chrome，不需要下载 Playwright 自带的 Chromium。

## 启动与使用

双击项目根目录的：

```text
start_web.bat
```

程序会打开：

```text
http://127.0.0.1:8765/
```

之后在网页中完成采集、登录继续、停止、查看、筛选和 Excel 导出。历史任务可勾选多条，使用列表顶部的刷新、合并导出、分别导出、删除图标；合并 Excel 注明任务来源，分别下载多个 Excel 不打 ZIP 包，浏览器可能需要允许多个文件下载。删除需确认，正在采集的记录不可导出或删除。关闭批处理命令窗口即可停止服务。

评论卡片右上角的私聊图标打开用户和消息面板，不显示原评论，抖音号与目标标识分行展示。填写内容后可直接点击“发送私信”：未打开会话时自动使用保存评论的 `sec_uid` 打开主页与私信，核对聊天会话 `sec_uid` 后才提交一条文本（工具限制 1000 字符），不做群发。“打开抖音私信”仍可单独使用，但不再是发送的前置操作；没有复制消息按钮。内容仅在点击发送时上传本机服务，不写入采集文件。发送凭据只处理一次；失败或超时不自动补发，界面提示已提交并不代表送达，必须到抖音核对实际结果。会话改变、已有抖音草稿、身份字段缺失、登录/验证或私信权限问题均停止并提示。打开及发送串行，各使用者使用自己的账号。浏览器在程序运行期间保持打开，采集结束不关闭私聊页，退出程序时关闭。当前使用主页入口，不拼接未经验证的直达私信 URL。聊天身份字段属于抖音内部页面结构，站点改版时会禁止直接发送，仍可在抖音人工处理。

批量私信：在结果页勾选评论旁的用户复选框，或使用“选择当前显示用户”（只选择当前已展示的评论），点击“批量私信”。预览会显示全部已选用户，包括被筛选隐藏的已选项；同一 `sec_uid` 自动去重。填写统一文本后点击“批量发送”，不需要另勾确认框。不限制每批人数，不额外添加固定间隔，仍按顺序核对会话并发送相同内容，与单条私信互斥。页面加载、会话核验和提交结果检查所需等待仍保留，平台自身限制不绕过。发送提交且输入框清空后关闭对应标签页；私密账号或已知权限限制跳过，登录/验证/未知异常/不确定提交结果停止剩余用户，不自动重试。可点击“停止后续发送”，当前正在执行的操作结束后不再派发下一位；已发送消息不会撤回。弹窗关闭不会停止，重新打开可查看逐用户结果。服务仍运行时刷新页面可查看进度，重启程序不会自动续发；消息和进度仅保存在内存，不写入评论 JSON。批量请求标识防止网络重复提交造成再次发送。“已提交”不等于送达，请以抖音记录为准。仅使用本人登录账号并遵守平台限制，不发送骚扰或垃圾信息。

批量任务的队列、统一配置和执行状态保存到 `src/config/batch_state.json`（当前及未完成任务）。页面刷新会读取 JSON 回显，不会重复启动采集；服务重启后未完成的队列标记为已中断，不自动重跑。页面日志显示当前视频的日志，每个视频的完整日志保存在对应目录的 `run.log` 中。 运行中的批次保留完整记录，页面仅显示未完成的视频；整批结束后清除成功任务记录，全部成功则删除任务记录文件。失败、停止、未启动和中断任务继续保留，新任务不会覆盖这些记录。

本地服务只监听 `127.0.0.1`，评论和图片不会上传到外部服务器。

主要代码文件直接位于 `src/`，网页服务入口为 `src/web_console.py`。

### 配置与任务持久化

开启并发采集后可设置同时运行的视频数量（1–100，默认 2），关闭开关时保持串行。并发数量与其他采集选项一起持久化；任务运行期间不能修改并发数量。高并发会增加内存占用及平台验证风险。

- `src/config/capture_settings.json`：首次启动自动创建，保存当前实际使用的采集参数，刷新和重启后回显，不保存视频链接。编辑设置后点击“保存修改”持久化，取消编辑会丢弃草稿。
- `src/config/capture_presets.json`：表格显示方案及“当前使用”标记，提供查看、编辑、应用和删除。末行“＋”加载系统默认参数供新增，点击“保存方案”后在弹窗输入名称；保存不会自动应用。下方默认显示当前配置，查看其他方案只预览，点击行内“应用”才切换。更新其他方案不改变当前配置。删除需确认，当前使用方案不能删除；存在其他方案时，未使用的默认配置可以删除，删除状态在重启后保留。至少保留一套配置，不删除采集结果。运行中可以查看，不能编辑或切换。
- `src/config/web_console_settings.json`：全局 XPath 配置，仍在高级配置页面单独保存。
- `src/config/batch_state.json`：只保存任务链接、运行状态及结果目录等队列信息，不重复保存采集配置。结束的任务不保留，队列全部结束后自动删除该文件；采集结果和日志保留在 `output/`。

## 使用原则

请只采集有权访问的公开内容，并遵守平台规则与适用法律。程序不会绕过验证码、滑块、登录限制或账号风险验证。建议使用保守的采集间隔，若频繁出现验证应停止任务并降低使用频率。
