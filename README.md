# 抖音评论调研工作台

本项目使用 Python 3.12、Playwright 和系统 Google Chrome，采集抖音一级评论文字及评论图片，并通过本地网页完成全部日常操作。

## 功能

- “并发采集”开关默认关闭；开启后最多同时采集两个视频，共用登录会话但独立监听评论、保存数据和日志。日志标记对应视频；队列每行的停止图标仅停止该视频，页面“停止整批”停止全部任务。遇到登录或验证会暂停派发新任务，手动处理后点击继续；并发会增加请求量和触发验证的可能性；

- 输入抖音视频链接后启动或停止采集；
- 高级配置分为“采集 XPath 配置”“采集接口配置”“回复 XPath 配置”。昵称与视频标题分别配置接口关键路径及点分 JSON 路径，默认接口 `/aweme/v1/web/aweme/detail/`，昵称 `aweme_detail.author.nickname`，标题 `aweme_detail.item_title`；统一保存到 `config/web_console_settings.json`。导航前监听，每页只接受与当前视频 ID 匹配的数据，不回退 HTML；未获取到时记录日志，结果显示作者未知/标题未知。留空停用对应字段，修改影响新任务，不回写历史结果。
- 视频输入框拒绝单独网址（包括带 modal_id 的链接），须粘贴分享文本；不要求文案包含特定词语，通过解析链接确定目标视频。这不是原文真实性验证，链接外附加文字仍可能通过。页面输入时检查重复，提示行号并清空后输入的重复框；不同短链指向同一视频时，在启动预校验中提示并清空后出现的重复行，需要重新点击启动。任意一条解析失败，弹窗列出输入行号和原因，整批均不开始采集。修改后重新点击启动，全部通过才创建队列；空行忽略。短链接最多五次跳转、总计 30 秒，不跟随外部域名、不猜推荐页当前视频。每个输入框仅支持一个目标视频；解析成功表示取得明确的视频 ID，不保证视频未删除或当前账号有访问权限。
- 视频链接默认显示一个输入框，点击每行右侧的“+”新增一行（最多 100 个）；忽略空行，自动去重后逐个采集，每个视频独立保存结果和日志，单个失败继续下一个，停止整批后不再启动剩余视频；
- 遇到登录、滑块或安全验证时，由用户在 Chrome 中手动完成，再在网页点击继续；
- 评论层级可选择“仅一级评论”（默认）或“所有层级评论”；
- 一级评论默认复用浏览器捕获的真实 `comment/list` 请求按游标分页；若接口签名失效、游标不前进或请求异常，会保留已有数据并自动切回页面滚动；
- “所有层级评论”采用两阶段采集：先快速加载完全部一级评论，再回到顶部逐段展开全部回复；该模式不会因评论数或运行分钟上限自动截断；
- 保存评论文字、作者、时间、IP 属地、点赞数、回复数及评论图片；
- 可开启“获取抖音号”（默认关闭）：评论采集后，优先使用评论接口的 `unique_id`；缺失时按 `sec_uid` 去重访问用户主页，读取 `user/profile/other` 响应的 `user.short_id`，回填 `author.unique_id`。同一任务内每位用户只补充一次；额外访问主页会影响性能、增加耗时；
- `author.unique_id_source` 标记抖音号来源：`comment_api`（评论接口）、`profile_api`（主页接口）。运行日志也逐用户说明来源；未获取到时保留空值，不使用内部用户 ID 替代；
- WebP 图片自动转换为 JPEG；
- 浏览历史结果、搜索评论、仅看带图评论、按点赞数或时间排序；
- 在网页中生成并下载 Excel；
- 每次采集建立新的 `output/<时间>-<视频ID>/` 目录。
- “评论回复”是独立任务：可粘贴多条完整分享文本，整批统一选择逐条弹窗确认或预设文字自动回复（在“设置”的“回复方式”下拉中选择，与“评论加载方式”同处一组），默认按顺序处理；在方案设置中开启“并发回复”后可设置 1–100 个同时处理的视频（默认 2），其余排队。省级 IP 属地和关键词可以同时筛选；多个关键词之间为 OR，与地区之间为 AND。当前只开放“页面元素优先（滚动加载）”，回复时使用配置的 XPath，按评论 ID 定位容器，再核对作者 `sec_uid`；无法唯一定位或身份不一致时不发送。“接口优先”暂不实现。每个视频只将命中评论及回复内容、结果写入 `output/reply_tasks/<时间>-<视频ID>/replies.json`，不把未匹配评论写盘。独立日志写入同目录 `reply.log`，页面右侧按视频分别显示。结果与导出页面可在“采集评论 / 评论回复”之间切换查看、筛选与导出。逐条发布不自动重试，响应无法确认时标记“结果不确定”。普通采集与独立回复任务不能同时运行。
- 评论回复的视频输入与采集页一致：单行只有“+”，多行最后一行显示“−/+”，其余行只有“−”，每行仅有分享文本输入框，不再有逐视频的回复方式或文案；重复分享文本会提示并清空后输入项。回复页的“设置”可保存多套命名方案，支持查看、编辑、应用、删除；方案含地区、关键词、加载方式、回复方式（实时逐条确认/预设文字自动回复）、预设回复文字、并发开关/数量和最长运行时间，不保存视频分享文本。“预设回复文字”仅在选择预设文字自动回复时显示，必填且最多 500 字，保存方案时即校验。查看不改变当前配置，启动只使用当前应用方案。

工作台页面按 Tab 维护：`src/web_console_parts/tabs/` 分别存放采集、回复、结果和高级配置；`components/` 放导航、免责声明等公共片段，`dialogs/` 放弹窗，`scripts/` 按功能分组，`styles.css` 放样式。`src/web_console.html` 是组合模板，`web_console.py` 返回页面时将这些片段组装成单个 HTML；不要直接双击模板文件预览。

右上角“使用教程”先选择评论采集、评论回复、结果与导出或高级配置，再在对应控件旁逐项显示说明。点击上一项/下一步手动翻步，最后完成教程；支持继续上次和从头学习，各模块阅读进度仅保存在当前浏览器。教程只切换页面、分类及展开设置，不会更改表单或执行保存、启动、发布、下载、删除。条件控件暂不可见时显示所在区域与操作提示，业务弹窗优先。教程定义、样式和脚本独立存放在页面资源目录，随 EXE 打包，常见问题保留在模块选择入口。

## Windows 首次安装

配置分为仓库配置与本机配置：`web_console_settings.json`（采集 XPath/接口）和 `comment_reply_xpath.json`（回复 XPath）继续提交 Git，并随 EXE 打包。采集参数、采集方案、回复方案在首次启动时按代码默认值自动生成，已有文件不会覆盖；默认只有“默认配置”，回复采用逐条确认、关闭并发，不预填筛选条件或回复文字。本机参数、方案、任务状态及免责声明确认记录不提交 Git、不随 EXE 分发；后两者仅在实际产生任务或确认时保存。源码配置位于 `src/config/`，EXE 配置位于程序同级 `config/`。

安装 Python 3.12 和 Google Chrome，然后在项目根目录执行一次：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
```

项目直接使用系统 Chrome，不需要下载 Playwright 自带的 Chromium。

## 启动与使用

双击项目根目录的：

```text
start_web.bat
```

程序会打开：

```text
http://127.0.0.1:8765/
```

之后在网页中完成采集、登录继续、停止、查看、筛选和 Excel 导出。历史任务可勾选多条，使用列表顶部的刷新、合并导出、分别导出、删除图标；合并 Excel 注明任务来源，分别下载多个 Excel 不打 ZIP 包，浏览器可能需要允许多个文件下载。删除需确认，正在采集的记录不可导出或删除。关闭批处理命令窗口即可停止服务。

评论卡片右上角的私聊图标打开用户和消息面板，不显示原评论，抖音号与目标标识分行展示。填写内容后可直接点击“发送私信”：未打开会话时自动使用保存评论的 `sec_uid` 打开主页与私信，核对聊天会话 `sec_uid` 后才提交一条文本（工具限制 1000 字符），不做群发。“打开抖音私信”仍可单独使用，但不再是发送的前置操作；没有复制消息按钮。内容仅在点击发送时上传本机服务，不写入采集文件。发送凭据只处理一次；失败或超时不自动补发，界面提示已提交并不代表送达，必须到抖音核对实际结果。会话改变、已有抖音草稿、身份字段缺失、登录/验证或私信权限问题均停止并提示。打开及发送串行，各使用者使用自己的账号。浏览器在程序运行期间保持打开，采集结束不关闭私聊页，退出程序时关闭。当前使用主页入口，不拼接未经验证的直达私信 URL。聊天身份字段属于抖音内部页面结构，站点改版时会禁止直接发送，仍可在抖音人工处理。

批量私信：在结果页勾选评论旁的用户复选框，或使用“选择当前显示用户”（只选择当前已展示的评论），点击“批量私信”。预览会显示全部已选用户，包括被筛选隐藏的已选项；同一 `sec_uid` 自动去重。填写统一文本后点击“批量发送”，不需要另勾确认框。不限制每批人数，不额外添加固定间隔，仍按顺序核对会话并发送相同内容，与单条私信互斥。页面加载、会话核验和提交结果检查所需等待仍保留，平台自身限制不绕过。发送提交且输入框清空后关闭对应标签页；私密账号或已知权限限制跳过，登录/验证/未知异常/不确定提交结果停止剩余用户，不自动重试。可点击“停止后续发送”，当前正在执行的操作结束后不再派发下一位；已发送消息不会撤回。弹窗关闭不会停止，重新打开可查看逐用户结果。服务仍运行时刷新页面可查看进度，重启程序不会自动续发；消息和进度仅保存在内存，不写入评论 JSON。批量请求标识防止网络重复提交造成再次发送。“已提交”不等于送达，请以抖音记录为准。仅使用本人登录账号并遵守平台限制，不发送骚扰或垃圾信息。

批量任务的队列、统一配置和执行状态保存到 `src/config/batch_state.json`（当前及未完成任务）。页面刷新会读取 JSON 回显，不会重复启动采集；服务重启后未完成的队列标记为已中断，不自动重跑。页面日志显示当前视频的日志，每个视频的完整日志保存在对应目录的 `run.log` 中。 运行中的批次保留完整记录，页面仅显示未完成的视频；整批结束后清除成功任务记录，全部成功则删除任务记录文件。失败、停止、未启动和中断任务继续保留，新任务不会覆盖这些记录。

本地服务只监听 `127.0.0.1`，评论和图片不会上传到外部服务器。

主要代码文件直接位于 `src/`，网页服务入口为 `src/web_console.py`。

源码运行时结果保存在项目根目录的 `output/`；EXE 运行时保存在 EXE 同级的 `output/`，启动后自动创建总目录。JSON、图片和日志均在各任务子目录内。程序所在目录需要有写入权限；既有用户数据目录中的历史结果不会自动移动。网页导出的 Excel 由浏览器下载设置决定保存位置。

`.douyin-browser-profile/` 保存专用 Chrome 的登录状态，不要同时运行多个工作台实例。

### 配置与任务持久化

开启并发采集后可设置同时运行的视频数量（1–100，默认 2），关闭开关时保持串行。并发数量与其他采集选项一起持久化；任务运行期间不能修改并发数量。高并发会增加内存占用及平台验证风险。

- `src/config/capture_settings.json`：首次启动自动创建，保存当前实际使用的采集参数，刷新和重启后回显，不保存视频链接。编辑设置后点击“保存修改”持久化，取消编辑会丢弃草稿。
- `src/config/capture_presets.json`：表格显示方案及“当前使用”标记，提供查看、编辑、应用和删除。末行“＋”加载系统默认参数供新增，点击“保存方案”后在弹窗输入名称；保存不会自动应用。下方默认显示当前配置，查看其他方案只预览，点击行内“应用”才切换。更新其他方案不改变当前配置。删除需确认，当前使用方案不能删除；存在其他方案时，未使用的默认配置可以删除，删除状态在重启后保留。至少保留一套配置，不删除采集结果。运行中可以查看，不能编辑或切换。
- `src/config/web_console_settings.json`：全局配置，包含暂停/私信按钮 XPath 和昵称/标题接口解析路径，在高级配置页面保存；先检查可见评论列表；同 ID 图文详情页未显示评论时，使用 X 快捷键打开评论。升级时按当前有效字段自动清理旧配置。
- `src/config/comment_reply_xpath.json`：独立评论回复 Tab 的评论容器、回复按钮、编辑器和发布按钮 XPath。评论容器 XPath 包含 `{comment_id}`；其余三项都相对于该评论容器，以 `.//` 开头。当前配置根据一条已展开回复的页面节点填写，网页可继续修改；页面结构变化时应重新核对，未实测真实发布成功。
- `src/config/reply_presets.json`：评论回复的当前应用设置、默认设置与命名方案；与视频链接和采集任务记录分开持久化，打包 EXE 时会带入默认文件，之后不会覆盖用户已保存的方案。
- “高级配置 → 采集 XPath 配置”必须填写并保存“私信按钮 XPath”。单条和批量私信共用此设置；未填写时提前停止，不打开主页，填写后定位失败也不自动尝试其他入口。输入框不显示示例或默认文本。按钮配置不跳过主页接口及聊天对象的 `sec_uid` 核验。
- `src/config/batch_state.json`：只保存任务链接、运行状态及结果目录等队列信息，不重复保存采集配置。结束的任务不保留，队列全部结束后自动删除该文件；采集结果和日志保留在 `output/`。

## 使用原则

请只采集有权访问的公开内容，并遵守平台规则与适用法律。程序不会绕过验证码、滑块、登录限制或账号风险验证。建议使用保守的采集间隔，若频繁出现验证应停止任务并降低使用频率。
## Windows 授权版 EXE

当前版本启动时必须验证授权签名、设备及有效期。首次双击显示激活窗口，粘贴管理员签发的完整授权码并点击“验证并激活”后才能打开工作台；后续有效授权自动通过。用户不需要安装 Python，但需要安装 Chrome，并使用自己的抖音登录账号。

打包前：管理员在 PyCharm 运行 `tools/license_issuer.py`，自动打开 `http://127.0.0.1:8787/` 的管理员 HTML 网页；Windows 也可双击 `start_license_issuer.bat`（需要已安装项目依赖的 Python 3.12）。不用启动或激活采集工作台，也不要直接双击 HTML 文件。

网页“生成密钥对”中输入至少 12 字符密码并确认，分别下载公钥和加密私钥，将私钥移动到项目之外的安全目录并备份密码，只将 `license_public_key.pem` 复制到 `src/licensing/`。用户先复制设备码发送给管理员，点击“下一步”输入授权码。管理员选择加密私钥、粘贴设备码、填写到期时间与密码，点击“生成并复制签名”将授权码发送给用户；不再填写或保存客户名称，也不再导出申请或下载授权文件。复制失败时可手动复制结果框，或点击“复制签名”，无需重新签发。管理员页面“反查授权码到期时间”可粘贴完整授权码，使用当前发行公钥验签后显示北京时间到期时间；已过期的真实授权码也能查询，篡改过的授权码会被拒绝。授权码以 `DYLIC2-` 开头，格式版本为 2，包含签名与设备/有效期载荷，编码不是加密；单独的签名字节不能激活。用户粘贴完整授权码激活，验签成功后仍保存到 EXE 同级文件夹中的 `licensing/license.lic`。旧版本授权文件及 `DYLIC1-` 授权码不兼容，需重新签发并重新打包客户端，但无需重新生成密钥。到期时间精确到秒，输入日期、时、分、秒均按北京时间解释，到达所选时刻即失效，不再自动延长到次日。

管理员网页仅绑定本机地址，接口有启动令牌、Host/Origin 校验及请求大小限制，不引用外部脚本。先上传加密 PEM 文件，再通过下拉框选择签发私钥；支持多份文件，同内容重复上传去重，同名不同内容用短标识区分。新生成的密钥需先下载备份再上传。上传只验证加密 PEM 封装，签发时才检查密码和 Ed25519 类型。文件记录包含名称及加密 PEM，保存到 `tools/admin_keys/`，与 `config/` 分离；Git 忽略该目录，打包清单禁止包含它及旧根目录 `admin_keys/`。旧目录文件不自动搬迁，继续使用时重新上传或停止工具后复制记录到 `tools/admin_keys/`，勿覆盖已有文件。重启恢复文件列表，密码不保存、不记日志，切换文件及签发结束后清空；列表不回传私钥内容。所选私钥须对应客户端内置公钥。删除副本需确认，不影响原文件、其他私钥或已签发授权。POSIX 文件权限为 600，新建目录为 700；Windows 使用目录系统权限。未下载或上传的临时密钥刷新即丢失。页面不提供退出服务功能，关闭标签不会停止服务；停止请使用 PyCharm 停止按钮或终端 Ctrl+C。分发项目时必须排除管理员工具及所有私钥目录。

在 Windows 上安装 Python 3.12，将项目复制到 Windows，在项目根目录打开 PowerShell，依次执行：

```powershell
py -3.12 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install --upgrade pip
.\.venv-build\Scripts\python.exe -m pip install -e .
.\.venv-build\Scripts\python.exe -m pip install "pyinstaller>=6,<7"
.\.venv-build\Scripts\python.exe -m PyInstaller --clean douyin_workbench.spec
```

生成文件为 `dist/抖音评论工作台.exe`。打包资源包括 HTML 模板及 `web_console_parts` 页面片段、五份 config 持久化配置、CustomTkinter 资源以及 `licensing/license_public_key.pem` 公钥；缺少公钥或公钥类型不正确时拒绝打包。任务队列、用户授权、管理员工具和私钥不打包。Mac 不能直接生成 Windows EXE，当前配置仍需在 Windows 实机验收。

EXE 的数据全部保存在程序所在目录：`output/` 保存采集结果和日志，`config/` 保存配置及队列状态，`.douyin-browser-profile/` 保存浏览器登录资料，`licensing/` 保存授权。源码开发保留项目根目录及 `src/config/` 布局。不使用 AppData 或单文件包的临时解包目录；EXE 应放在有写入权限的文件夹中。旧 AppData 数据不自动搬迁；需要保留时，退出程序后将旧 `src/config/` 内文件复制到新的 `config/`，旧 `output/` 和 `.douyin-browser-profile/` 复制到 EXE 同级，勿覆盖已有数据。浏览器资料含登录状态，请勿分享给其他用户。

首次启动将包内四份默认配置复制到 EXE 同级的 `config/`；之后仅补齐缺失文件，不覆盖用户已经修改的配置。更新 EXE 也不会重置已有设置。

Windows 验收：未安装 Python 的电脑双击启动；首次 Chrome 登录；采集、停止、图片展示和 Excel 导出；重启后配置及结果保留。EXE 运行时在任务栏右下角系统托盘显示图标（可能折叠在“显示隐藏图标”中），右键可选择“打开工作台”或“退出”。关闭网页标签不退出后台；选择“退出”会停止服务、清理采集/私信任务及浏览器连接，再移除图标。托盘不是任务栏中间的独立窗口按钮。源码启动保持原方式。

## 签名认证与 NTP 时间

Windows EXE 使用单实例运行：重复双击仅打开已有工作台，不增加托盘图标或重复启动采集。正常退出或进程异常结束后，Windows 自动释放实例对象，可以再次启动；源码开发不受此限制。

授权采用 Ed25519 签名，固定公钥验证后核对设备、产品、签发和到期时间。NTP 列表包含阿里云 `ntp.aliyun.com`、`ntp1.aliyun.com` 至 `ntp7.aliyun.com`，腾讯云 `ntp.tencent.com`、`ntp1.tencent.com` 至 `ntp5.tencent.com`，采用两家官方公布的公网地址：[阿里云文档](https://help.aliyun.com/en/ecs/user-guide/alibaba-cloud-ntp-server/)、[腾讯云文档](https://intl.cloud.tencent.com/document/product/213/32379?lang=en)。查询先尝试两家主地址，再交替尝试备用；一条成功即停止。只交换标准 NTP 时间数据，不发送设备码、授权、登录资料或评论。需允许 UDP 123；全部失败拒绝使用，不回退本机时间。

每次启动重新取时；每条地址超时约 2 秒，14 条均超时约 28 秒。运行期用网络 UTC 加单调时钟推进，每五分钟重新校时，不依赖本机墙上时钟或旧 clock.json。页面/API 操作前再次验签，采集任务写入队列前额外复验，每两秒检查期限；授权到期、被修改或重新取时失败会拒绝业务接口，并安全停止当前采集及后续批量私信，已保存结果保留，已提交的私信无法撤回。HTTP 服务保留以便显示授权错误，不继续采集；页面会显示“授权已过期”并禁用启动，刷新仍可显示页面外壳但不能读取业务数据。重新联网或取得续期授权后退出并重启，窗口支持“重新验证已有授权”。

标准公网 NTP 无密码学认证；请求随机标记、响应来源、服务器模式/同步状态及时间戳校验可以过滤无关/异常报文，但不能防止有能力的网络攻击者、DNS 劫持或客户端修改。设备绑定使用 MachineGuid/平台 UUID，不承诺不可克隆。本版仍需验证 Windows 激活窗口、UDP 防火墙、首次导入、重启、到期和续期流程。

授权文件与普通配置隔离：公钥读取位置为 `src/licensing/license_public_key.pem`（EXE 内置资源为 `licensing/`），不受运行授权目录影响。客户端验证授权码通过后，自动在 EXE 同级建立 `licensing/`，保存为 `licensing/license.lic`；源码运行时位于项目根目录下的 `licensing/`，后续启动读取该文件。旧根目录或旧用户目录中的授权不再读取，请重新输入授权码；旧文件不会自动删除。删除运行目录的 `licensing/license.lic` 可清除本机激活。EXE 所在目录必须可写，不能写入时明确提示保存失败，不回退到其他目录。管理员私钥仍保存在项目外的安全目录，禁止放入 `config/` 或发行包。旧 clock.json 不再作为期限依据。
# 加载失败重试

评论采集、评论回复的配置方案均支持“失败重试次数”（默认 3，范围 0～10，0 表示不重试）。首次尝试不计入重试次数；每个视频、分页或用户资料分别计算，恢复有效进展后重置。失败回复达到上限会跳过；整个评论列表无法推进则停止当前视频并保留已有数据，日志注明结果可能不完整，其他视频继续。人工确认不计入失败次数；发布评论和私信不会因此自动重发。

接口成功返回 `comments: null` 时直接跳过当前视频或当前回复列表，不再重试，保留已采集数据并继续后续任务。

评论回复任务在评论区打开后，最多等待 45 秒接收首批评论数据；分页暂时没有进展时等待 15 秒，再计一次加载失败。数据或滚动位置有进展会重新计时，接口明确返回已到底时正常结束。人工登录和验证等待不占用这些加载等待时间。

图文分享与视频分享使用相同入口，按作品 ID 去重。页面跳转到同 ID 的 `/note/` 图文页时，采集和回复任务会在评论尚未显示时使用 X 快捷键打开评论，只读取和滚动可见评论列表；同一浏览器上下文中的多个任务会协调切换标签页并按键，避免并发抢占焦点。每轮等待最多按一次 X，按键后保留完整加载等待，未显示时按失败重试次数限制重新尝试；评论已显示时不再按键。图文详情初始化共用最长 45 秒就绪等待，未就绪时不按 X、不消耗按键失败重试次数；同作品跳转导致评论面板读取上下文失效时，重新核对域名和作品 ID 后按同一失败重试预算恢复，并记录检查阶段与不含查询参数的页面地址。作品 ID 变化会停止操作，发送结果不确定时不会自动重发。
